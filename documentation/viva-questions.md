### 1. General NoSQL & MongoDB Concepts

#### Q1. What is NoSQL and how does it differ from traditional Relational Databases (RDBMS)?
**Answer**:
NoSQL stands for *"Not Only SQL"*. While RDBMS enforces a fixed tabular schema of rows and columns with strict ACID constraints and relational joins, NoSQL databases provide:
- **Flexible Schemas**: Documents or records do not need to adhere to the exact same column structures.
- **Horizontal Scalability (Sharding)**: Designed to scale across distributed clusters rather than requiring larger vertical hardware.
- **Optimized Data Models**: Supports document, key-value, column-family, and graph data representations.

#### Q2. What type of NoSQL database is MongoDB?
**Answer**:
MongoDB is a **Document-Oriented NoSQL Database**. It stores data as self-contained BSON (Binary JSON) documents. Each document contains field-value pairs where values can be primitive types, arrays, or nested subdocuments.

#### Q3. Compare Database vs. Collection vs. Document in MongoDB with RDBMS equivalents.
**Answer**:
| MongoDB Concept | RDBMS Equivalent | Description |
| :--- | :--- | :--- |
| **Database** | Database / Schema | Physical container for collections. |
| **Collection** | Table | Grouping of related documents (schema-free/schema-flexible). |
| **Document** | Row / Record | Single data record stored in BSON format. |
| **Field** | Column | Key-value attribute within a document. |
| **`_id`** | Primary Key | Unique 12-byte identifier automatically indexed. |

#### Q4. Why did you partition your e-commerce project into 6 separate databases instead of 1?
**Answer**:
In enterprise distributed systems, bounded contexts and Microservice Architecture dictate domain isolation. By creating `customer_db`, `product_db`, `order_db`, `inventory_db`, `payment_db`, and `analytics_db`, each microservice independently manages its data storage without cross-service database locks, mirroring real-world systems like Amazon or Flipkart.

#### Q5. What is the role of the MongoDB Atlas Cloud Cluster in your architecture?
**Answer**:
MongoDB Atlas provides a cloud-managed database deployment featuring replica set redundancy, automatic failover, wire-level TLS encryption, automated backups, and sharding capabilities, ensuring production readiness.

#### Q6. What is the difference between Schema-less and Schema-Flexible?
**Answer**:
MongoDB is **Schema-Flexible**, not strictly schema-less. Documents in the same collection do not need identical fields, but business applications still enforce logical structure. MongoDB also supports optional JSON Schema Validation at the collection level via `validator` rules.

### 2. Data Model, BSON & ObjectId

#### Q7. What is BSON, and why does MongoDB use BSON instead of plain JSON?
**Answer**:
BSON stands for **Binary JSON**. While JSON only supports basic data types (string, number, boolean, array, object, null), BSON extends JSON with:
- Native binary encoding for faster traversal and parsing.
- Additional data types: `ObjectId`, `Date` (64-bit integer UTC timestamp), `Int32`, `Int64`, `Decimal128` (precise floating point for currency), and raw binary data.

#### Q8. What is an `ObjectId` and what is its internal composition?
**Answer**:
An `ObjectId` is a 12-byte unique identifier generated by MongoDB for the `_id` field. Its structure consists of:
- **4-byte timestamp**: Unix epoch seconds representing document creation time.
- **5-byte random value**: Unique to the machine and process generating the ID.
- **3-byte incrementing counter**: Initialized to a random value to ensure collision resistance.

#### Q9. How do you extract the creation date from a MongoDB `ObjectId`?
**Answer**:
Using the helper method `getTimestamp()`:
```javascript
ObjectId("65f1a2000000000000000001").getTimestamp();
// Output: 2024-03-13T12:30:00.000Z
```
Because the timestamp is embedded in the first 4 bytes, ObjectIds are naturally sorted chronologically.

#### Q10. What data types are demonstrated in your project's documents?
**Answer**:
Our project utilizes 7 native BSON types:
1. `ObjectId` (primary keys)
2. `String` (identifiers, descriptions, statuses)
3. `Number` (prices in INR, quantities, dimensions)
4. `Boolean` (KYC verification, active flags)
5. `Date` (registration, order, and dispatch timestamps)
6. `Array` (product tags, user interests, order tags)
7. `Object` (nested coordinates `{ latitude, longitude }`, metadata)

#### Q11. Why did you use INR for monetary fields instead of storing numbers as plain strings?
**Answer**:
Storing monetary amounts as BSON Numbers (e.g. `sellingPriceINR: 59999`) allows MongoDB to perform mathematical comparisons (`$gte`, `$lte`), numerical range indexing, and mathematical aggregations (`$sum`, `$avg`, `$min`, `$max`), which is impossible with strings.

#### Q12. How does MongoDB handle timestamps across different time zones?
**Answer**:
MongoDB stores `Date` objects as 64-bit signed integers representing milliseconds since the Unix epoch (Jan 1, 1970) in **UTC**. The client driver converts UTC to local time when rendering.

### 3. CRUD Operations & Mutation Methods

#### Q13. What is CRUD in MongoDB?
**Answer**:
CRUD represents the four fundamental persistent storage operations:
- **C**reate: `insertOne()`, `insertMany()`
- **R**ead: `find()`, `findOne()`
- **U**pdate: `updateOne()`, `updateMany()`, `replaceOne()`
- **D**elete: `deleteOne()`, `deleteMany()`

#### Q14. What is the difference between `find()` and `findOne()`?
**Answer**:
- `find(query)`: Returns a **cursor** that points to a stream of matching documents, allowing method chaining such as `.sort()`, `.skip()`, and `.limit()`.
- `findOne(query)`: Returns the **first matching document directly** (or `null` if not found), without returning a cursor.

#### Q15. Why should you use update operators like `$set` instead of replacing the document?
**Answer**:
If you call `updateOne(filter, { status: "ACTIVE" })` without `$set`, MongoDB throws an error in modern drivers because it requires atomic update operators. The `$set` operator replaces only the specified field values without overwriting or destroying the remaining fields in the document.

#### Q16. What is the difference between `$push` and `$addToSet` in MongoDB updates?
**Answer**:
- `$push`: Appends the specified value to an array unconditionally, even if the value already exists (permits duplicates).
- `$addToSet`: Treats the array as a mathematical set; it appends the value **only if it does not already exist**, preventing duplicate tags or preferences.

#### Q17. What does the `$currentDate` update operator do?
**Answer**:
The `$currentDate` operator sets the value of a field to the current server timestamp (either as a BSON Date or BSON Timestamp). It avoids clock skew between client application servers.

#### Q18. What is the difference between `deleteOne()` and `deleteMany()`?
**Answer**:
- `deleteOne(filter)`: Removes the first document matching the filter criteria.
- `deleteMany(filter)`: Removes all documents that match the filter criteria in the collection.

### 4. Query Operators & Filtering

#### Q19. Name the primary Comparison Operators in MongoDB and their functions.
**Answer**:
- `$eq`: Matches values equal to a specified value.
- `$ne`: Matches all values not equal to a specified value.
- `$gt`: Matches values greater than a specified value.
- `$gte`: Matches values greater than or equal to a specified value.
- `$lt`: Matches values less than a specified value.
- `$lte`: Matches values less than or equal to a specified value.
- `$in`: Matches any value in a specified array.
- `$nin`: Matches no values in a specified array.

#### Q20. Explain the Logical Operators (`$and`, `$or`, `$not`, `$nor`).
**Answer**:
- `$and`: Joins query clauses with logical AND; returns documents matching all conditions.
- `$or`: Joins query clauses with logical OR; returns documents matching at least one condition.
- `$not`: Inverts the effect of a query expression.
- `$nor`: Joins query clauses with logical NOR; returns documents that fail all clauses.

#### Q21. How do you query nested fields in an embedded document in MongoDB?
**Answer**:
Using **Dot Notation** enclosed in quotes. For example, in our `inventory_db.warehouses` collection:
```javascript
db.warehouses.find({ "geoCoordinates.latitude": { $gte: 12.0, $lte: 19.5 } });
```
MongoDB directly accesses the inner `latitude` property inside the `geoCoordinates` object.

#### Q22. What is the difference between `$in` and `$all` when querying array fields?
**Answer**:
- `tags: { $in: ["5G", "Flagship"] }`: Returns documents whose `tags` array contains **either** `"5G"` OR `"Flagship"` (or both).
- `tags: { $all: ["5G", "Flagship"] }`: Returns documents whose `tags` array contains **both** `"5G"` AND `"Flagship"`, regardless of array order or extra elements.

#### Q23. What is Field Projection and why is it important?
**Answer**:
Projection specifies which fields to return in the result set (`1` to include, `0` to exclude).
```javascript
db.products.find({}, { projection: { name: 1, sellingPriceINR: 1, _id: 0 } });
```
It minimizes network bandwidth, reduces RAM consumption, and speeds up query execution.

#### Q24. How does sorting work in MongoDB, and what do `1` and `-1` represent?
**Answer**:
- `1` specifies **Ascending** order (smallest to largest / A to Z).
- `-1` specifies **Descending** order (largest to smallest / Z to A).
```javascript
db.orders.find().sort({ totalAmountINR: -1 }).limit(5); // Top 5 highest orders
```

### 5. Aggregation Framework & Pipelines

#### Q25. What is the MongoDB Aggregation Pipeline?
**Answer**:
The Aggregation Pipeline is a multi-stage framework for data transformation and analytics modeled on the concept of data processing pipelines. Documents enter a multi-stage pipeline where each stage transforms the documents (e.g. filtering, grouping, reshaping, sorting) and passes the results to the next stage.

#### Q26. Explain the roles of `$match`, `$group`, `$sort`, and `$limit`.
**Answer**:
- **`$match`**: Filters documents to allow only matching records to pass to the next stage (equivalent to SQL `WHERE` or `HAVING`). Should be placed early in the pipeline to use indexes.
- **`$group`**: Groups input documents by an identifier expression (`_id`) and applies accumulator expressions (`$sum`, `$avg`, `$min`, `$max`, `$push`).
- **`$sort`**: Reorders documents by specified fields (`1` or `-1`).
- **`$limit`**: Restricts the number of documents passed to the next stage.

#### Q27. What does the `$unwind` stage do, and when is it necessary?
**Answer**:
`$unwind` deconstructs an array field from the input documents to output one document for *each* element of the array.
For example, if a product has `tags: ["5G", "Flagship"]`, `$unwind: "$tags"` outputs two documents: one with `tags: "5G"` and another with `tags: "Flagship"`. It is essential when calculating tag frequency or average prices per tag.

#### Q28. What is the `$lookup` stage in MongoDB?
**Answer**:
The `$lookup` stage performs a left outer join to an unsharded collection in the same database. It matches fields between documents and adds the matched documents as an array field:
```javascript
{
  $lookup: {
    from: "order_items",
    localField: "orderId",
    foreignField: "orderId",
    as: "lineItems"
  }
}
```

#### Q29. What accumulator operators are commonly used inside `$group`?
**Answer**:
- `$sum`: Calculates the total sum or increments a count (`{ $sum: 1 }`).
- `$avg`: Calculates the mathematical mean average.
- `$min` / `$max`: Identifies lowest / highest values.
- `$first` / `$last`: Obtains boundary values in sorted streams.
- `$push` / `$addToSet`: Accumulates array values across grouped documents.

### 6. Data Modeling: Embedding vs. Referencing & Joins

#### Q30. Explain the difference between Embedded Data Models and Normalized (Referenced) Data Models.
**Answer**:
- **Embedded (Denormalized)**: Related data is stored inside a single document as nested objects or arrays.
  - *Advantage*: Atomic reads/writes in a single operation, zero join overhead.
  - *Use Case*: 1-to-1 or 1-to-Few relationships where child data is always accessed with parent (e.g., shipping coordinates in a warehouse).
- **Referenced (Normalized)**: Related data is stored in separate collections and linked via ID fields.
  - *Advantage*: Prevents document size bloat (MongoDB document limit is 16MB), eliminates data redundancy.
  - *Use Case*: 1-to-Many or Many-to-Many relationships, high-frequency independent updates (e.g., customers and orders).

#### Q31. What is the 16MB document size limit in MongoDB?
**Answer**:
A single BSON document cannot exceed 16 Megabytes. This threshold prevents memory hogs, ensures high-performance network transfer, and encourages developers to normalize large arrays (like unbounded log history) into separate collections using references.

#### Q32. How does your project balance embedding and referencing?
**Answer**:
We utilize a hybrid model:
- **Embedded**: High-affinity, bounded data like `geoCoordinates` inside `warehouses`, `activityMetadata` inside `customer_activity`, and `tags` inside `products`.
- **Referenced**: Bounded contexts and large-scale relational entities like `orders` referencing `order_items`, `customers`, and `payments` via `orderId`, `customerId`, and `paymentId`.

#### Q33. What are the 3 `$lookup` join relationships demonstrated in your project?
**Answer**:
1. `order_db.orders` $\leftrightarrow$ `order_db.order_items` on `orderId` (Master orders with itemized products).
2. `product_db.products` $\leftrightarrow$ `product_db.product_variants` on `productId` (Catalog items with color/storage SKUs).
3. `order_db.orders` $\leftrightarrow$ `order_db.delivery_addresses` on `orderId` (Orders with legal shipping destinations).

### 7. Advantages, Trade-Offs & Scaling

#### Q34. What are the key advantages and limitations of MongoDB?
**Answer**:
- **Advantages**:
  1. *Schema Flexibility*: Accommodates rapid product catalog changes without `ALTER TABLE` migrations.
  2. *Performance*: Native document embeddings eliminate multi-table relational join bottlenecks.
  3. *High Availability*: Automated replica set failover with zero manual intervention.
  4. *Native Sharding*: Transparent horizontal data partitioning across commodity clusters.
- **Limitations**:
  1. *Memory Overhead*: BSON key names are repeated in every document (can be mitigated with field compression).
  2. *Join Performance*: `$lookup` is not designed for deep multi-level relational OLAP joins across thousands of sharded collections.
  3. *16MB Document Limit*: Unbounded array growth requires architectural vigilance.

#### Q35. How does MongoDB achieve High Availability and Horizontal Scalability?
**Answer**:
- **High Availability (Replica Sets)**: Uses a cluster of MongoDB servers where one is Primary (handles writes) and two or more are Secondaries (replicate data via `oplog`). If the Primary fails, an automated election promotes a Secondary in seconds.
- **Horizontal Scalability (Sharding)**: Distributes data across multiple nodes (shards) using a *shard key*, allowing the system to scale horizontally to petabytes of storage.
